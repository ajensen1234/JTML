* Executive Summary

The single highest-leverage finding of this run: **the current 0.9936 IoU baseline is measured against a deterministically-corrupted cost term.** Angle 02 verified at the dispatch's line numbers that the distance-map index formula (distance_map_metric.cu:27, `blockIdx.y + gridDim.x` instead of `blockIdx.y * gridDim.x`) mis-maps every block row, so the distance-map term of every DIRECT_DILATION oracle evaluation accumulates at the wrong pixels. That is the one live bug of the seven verified — the other six poison latent paths only. Fixing it and re-baselining (one single re-baseline after all behavior-neutral fixes land) is the prerequisite for every other decision in this run: variant switches, perf cuts, and gradient polish are all judged against a baseline that is not trustworthy until this lands. The gate (IoU ≥ 0.85) is far below the measured 0.9936, so the appearance arbiter stays, but measured IoU / per-px L1 / the 6.31 mm z gap are informational and expected to move.

Round 2 sharpened the critical path in an important way: the corrupted index has **exactly one reader** (DistanceMapMetric_Kernel, invoked only from DIRECT_DILATION.cpp:80), and every post-optimize measurement metric (IoU, per-px L1, chamfer) uses the correct formula — so the 0.9936/0.0207 numbers themselves are not corrupted, only the cost that drove the search. The corruption is a systematic exclusion: the top ~64 crop rows of the rendered band are never sampled and the middle band is multiplicity-over-weighted, so the distance-map term is *flatter in z* than the honest chamfer complement. The structural prediction is that the re-baselined DIRECT optimum moves toward the golden z and the frame-1 6.31 mm z gap shrinks materially (direction: medium-high confidence; magnitude: not predictable without the GPU re-run).

Round 2 wave 2 added two more high-value deliverables on top of the wave-1 deepening. **First, the ms/call meter carries a 1000× unit error on Linux, on top of its CPU-time blind spot**: grep finds zero CLOCKS_PER_SEC anywhere in src/ — both meter sites (optimizer_manager.cpp:1197-1203 end-of-frame and :1272-1279 iteration callback) divide raw clock() ticks by calls and label the result "ms/call"; on Linux glibc clock() returns microseconds, so the value is CPU-µs/call labeled as ms/call. The UI compounds it: "Iterations Per Second: 1000.0 / iteration_speed" (mainscreen.cpp:4654-4655) reads the µs value as ms → IPS understated ~1000×, and the ETA (:4598/:4659) is overstated by the same factor. This is a correctness fact, not polish — no before/after perf claim through the existing meter is meaningful, and Cut 4 (now a full spec for BOTH sites) must emit true ms/call so the existing UI math becomes correct without UI changes. [Source: angles/05-compute-perf.org R2-1/R2-2] **Second, the polish stage is now an executable MVP spec with its own falsifiable preconditions**: a term-decomposed z-profile probe (chamfer-only vs dilated-overlap-only valley depths from the same 31 renders, pre-registered thresholds G1–G4 at leaf dilation 1), a forward-difference arm (7 renders/accepted step, ~140 steps within B_p = 1000), an analytic arm (1 render/step via the 2×6 projection Jacobian + gradient-of-distance-map kernel, with an ordered two-pass float reduction so the ablation runner's rerun_identical determinism twin cannot trip), and a **three-arm study (A: DIRECT@35k, B: DIRECT@34k budget-gift control, C: DIRECT@34k + polish@1000)** that arbitrates the 12x-vs-1.5–3x contradiction without confounding "polish quality" with "budget reallocation". [Source: angles/06-differentiable-polish.org R2-1/R2-2/R2-4/R2-5]

The recommended course of action, in dependency order, is unchanged in shape and now fully specified in content: (1) pin-first fixes per angle 02 (Tier-0 pins, behavior-neutral fixes, the distance-map index fix + one oracle re-baseline — plus the CUDA-free finite-check at DirectOptimizer::EvaluateCostFunction, needed regardless of GLh); (2) the measurement apparatus per angle 03 — the z-profile probe on the RunDirectStage injected-cost lambda (now an executable 31-render spec that also arbitrates the polish precondition G1–G4 via its term-decomposition mode) and the production-shaped multi-stage oracle through the plan-006 OptimizerRunDriver seam, which **no longer needs the "small seam addition"**: Round 2 proved Directive::SymTrap already exists in the typed enum, so the tibia-ambiguity pass is three pins, not a code change; (3) the ablation runner + ablation.json (schema now complete, plus the perturbation suite that calibrates the IoU gate's checked coverage); (4) the evidence-backed algorithm upgrade from angle 01 — **1-DTC-GL-gb** — now with a concrete analytic battery (22 n=5 problems + Hartman6, GKLS classes, pe≤1e-2), a quantified split tie-break divergence (a faithful GL landing requires switching the repo's largest-denormalized-side rule to the study's least-split rule), and a gb-semantics caveat (the DIRECTGO reference code toggles the phases inverted relative to the paper's prose — implement the canonical semantics plus an ablation arm replicating the code as shipped); (5) compute-perf cuts 0–4 per angle 05 — now executable recipes (instrumentation protocol, async terminal copies, iteration batching on the double-buffered seam contract, the conditional fragment-fill removal proven bit-safe by in-kernel guards, and a meter fix that also corrects the 1000× unit error), every cut gated on oracle green + bit-identical cost values with a revert rule; (6) the differentiable-polish stage per angle 06 — now an executable MVP (chamfer-surrogate gradient, precondition gate G1–G4, FD then analytic arms) arbitrated by the three-arm study that removes the budget-gift confound from the 12x-vs-1.5–3x question. Architecture work (angle 04) flows through as additive cuts A–F.

Two tensions the user should carry explicitly. First, **the variant switch cannot fix the z-axis**: Round 2 resolved this from a scoping tension into an explicit mechanism analysis — the variant choice (search scheme) and the z-sensitivity ranking (cost observability) are orthogonal in mechanism, with only two documented second-order interactions (the NaN/Inf trigger and refinement-control savings on z-flat costs); the harness must report evals and z-error separately, and a variant-switch win must never be read as a z fix. The real z remedies remain biplane (already supported) or a known-geometry prior, and every z remedy is gated on angle 03's probe. Second, **perf cuts do not sacrifice determinism**: every active cost-path reduction is an int atomicAdd (order-independent, value-deterministic), so async copies and iteration batching can preserve bit-identical results; angle 04's Round-2 seam contract pins the double-buffered eval state (compute owns the buffer state, the manager owns the object graph, the domain sees only std::function). Wave 2 extends this doctrine to the polish: the gradient must use an ordered (non-atomic) float reduction, because the ablation runner's rerun_identical determinism twin would trip on float-atomic accumulation.

Round 2 also closed the run's longest-standing open question: **the DIRECT-GLh NaN trigger is now resolved per-variant.** DIRECT_DILATION is structurally incapable of emitting NaN/Inf (all-int composition, +0.1-guarded division, max accumulation 2.55e8 ≪ 2³¹) — the GLh trigger lives in DIRECT_MAHFOUZ (0/0 via the pointer-guard bug, production-reachable), DD_NEW_POLE_CONSTRAINT (UB min_dist), and sym_trap (asin domain). The finite-check belongs at the one shared chokepoint, DirectOptimizer::EvaluateCostFunction (direct_optimizer.cpp:205), and the round-1 claim that "NaN poisons hull slope comparisons" is corrected: NaN boxes accumulate as dead weight at the column front (lost evals, unbounded growth), with the column minimum poisoned only after all finite boxes are trisected away — a delayed, conditional effect, still worth closing. The "12x fewer evals" polish thesis remains a target to test, not a justification: angle 06's analysis puts the realistic win at ~1.5–3× in the leaf/refinement phase, with the chamfer distance-map surrogate as the one smooth gradient signal — and wave 2's three-arm study is the instrument that will measure it. Everything else from the papers — 1-DTDV boundary sampling, analytic-AA occlusion gradients, DRR-photometric gradients, torch bridges — stays conditional, deferred, or NO-GO, and each lands only through the harness.
