#+TITLE: Angle 01 — Signal Engineering: Which Projection Features Break Rotational Symmetry, and What Cannot (Evidence for the Cost-Function Seam)
#+DATE: 2026-08-14
#+PANOPTES_ANGLE: 01-01-signal-engineering

* Summary
For parts with a *continuous* rotational symmetry (hip stem shank, femoral head,
cylindrical cup), the attenuation projection is *provably invariant* under rotation about
the symmetry axis: every function of the image — silhouette, intensity, gradient,
curvature, MI, learned — is invariant, so NO single-plane cost function can recover that
DOF, regardless of feature engineering. The literature independently confirms this floor
(D'Isidoro & Ferguson 2018; dental cylindrical-implant study 2021; known-component
registration modeling screws as 5-DoF). For the knee femoral component there is no exact
continuous symmetry: all 6 DOF are in principle recoverable, but varus/valgus and depth
are *ill-conditioned* (near-circular condyle arcs ⇒ first-order-flat silhouette basins;
Yamazaki 2004 measured a "less pointy" depth curve). That conditioning can be rescued by
two-sided intensity/attenuation and gradient-orientation features — but the repo's
renderer produces only flat-fill white silhouettes, and DIRECT_MAHFOUZ's "intensity" term
is one-sided (fluoroscopy sampled under the template silhouette), so neither is currently
available. The curvature story: the GPU metric was never implemented (stub returns 0.0)
AND a fair test was never specified (undefined semantics), AND local curvature is a
second-order, noise-amplified feature that is itself invariant for circular boundaries —
the mismatch between a local feature and a global symmetry ambiguity is real, but a
globally aggregated contour-curvature term could in principle work at a tight per-eval
budget. Verdict: the owner's assumption "the current cost functions don't provide enough
signal" survives for the KNEE conditioning DOFs (cheapest fix surface: two-sided
intensity + GO features in a new cost variant); it does NOT survive for symmetric
hip/shoulder parts, where the missing signal is absent from the projection itself and the
fix is external reference / priors / dyads (angle 02).

* Research Questions (accountable)
1. Which projection features are provably non-invariant under rotation about an implant's symmetry axis, and what evidence shows they are usable in monoplane fluoroscopy 2D-3D registration?
2. Which of those are computable in a ~143 µs/eval GPU loop (kernel + sync budget, RTX 3090 Ti)?
3. What does the literature say about intensity-inside-silhouette, gradient/phase, curvature-as-feature, and multi-feature fusion for implant registration (Mahfouz, Yamazaki, Flood, gradient-correlation family)?
4. For each candidate feature: does it break CONTINUOUS rotational symmetry (stems, heads) or only MIRROR symmetry (cups, glenoids)?
5. Is there a provable information floor — is the symmetric DOF recoverable from ANY single-plane projection, or only from shading/attenuation cues monoplane X-ray cannot supply?

* Findings
** Finding 1 — The information floor is provable, and four independent sources confirm it: rotation about a continuous symmetry axis is unrecoverable from a single-plane projection of that part, by ANY image feature.
- Proof sketch: for a homogeneous shape S with rotational symmetry R_a(θ)S = S, the
  ray-attenuation integral through R_a(θ)S equals that through S (rotation is
  measure-preserving). Hence every pixel of the DRR, and every statistic of the DRR
  (silhouette mask, interior intensity, gradient magnitude/phase, boundary curvature, MI
  joint histogram, learned features), is exactly invariant. This holds for any single
  view; even scatter/beam hardening are functions of the same invariant path-length
  distribution. Only features that break the *geometric* symmetry itself (collar, neck,
  fins, non-circular cross-section, machining bevels, asymmetric attachments) can break
  the image invariance.
- Corroboration: D'Isidoro & Ferguson 2018 (cup rotation "cannot be uniquely determined
  with the sole use of contours"; fix = pelvic-bone reference) [Source: cmbbe2018 PDF];
  dental implant 2021 ("did not have enough information... to resolve all degrees of
  freedom"; fix = extra non-collinear reference point) [Source: PMC7937219]; Otake KC-Reg
  2018 (screws deliberately modeled as 5-DoF) [Source: PMC5901722]; TREA patent (extra
  measurement configurations required for symmetric implants) [Source: trea.com].
- Relevance: JTML has zero hip/shoulder models; if those enter scope, the symmetric DOF
  (stem version for a circular-section stem, cup rotation for a cylindrical cup) is a
  floor, not a signal problem. No cost function in the seam can fix it; the fix is
  external reference (D'Isidoro's pelvic-bone route), kinematic priors, dyads (angle 02),
  or multi-view. Angle 05's geometry taxonomy should classify each implant's weak DOF as
  continuous-floor vs mirror-ambiguous vs merely ill-conditioned.
- Confidence: high (mathematical; 4 independent corroborations).

** Finding 2 — For the knee femoral component there is NO exact continuous symmetry: all 6 DOF are theoretically recoverable from one plane. The weak DOFs are a conditioning problem (first-order-flat cost basins), and two-sided intensity/GO features are the documented rescue.
- The condyle arcs are near-circular in the coronal-ish projection; rotation about the AP
  axis (varus/valgus) maps the arc nearly onto itself ⇒ silhouette overlap changes only at
  second order ⇒ flat basin. Yamazaki 2004 is the canonical demonstration for the sibling
  weak DOF (depth): "only small changes in the 2-D silhouette"; the depth evaluation curve
  was "more jagged, and the curve peak less pointy" — and their improvement (2.6→0.9 mm
  sim, 3.2→1.4 mm vitro) came from optimization structure, not new features [Source:
  europepmc MED/15147013]. The repo's own z_profile instrument (6.31 mm gap) measures
  exactly this phenomenon.
- Rescue features, in evidence order: gradient orientation (GO) — 0% gross failures under
  implant/instrument content mismatch where plain gradient correlation failed >14% (De
  Silva 2016) [Source: IOPscience PDF]; gradient correlation (Penney 1998; used for
  component pose in Otake KC-Reg) [Sources: doi 10.1109/42.730403; PMC5901722]; pattern
  intensity (robust to structures present in only one image — exactly the bone/cement
  content-mismatch situation in TKA fluoroscopy) [Sources: Weese SPIE 3661; Med Phys 2005
  formula]; normalized gradient information (Otake 2013) [Source: IOPscience].
- Why this matters locally: the only rotation-sensitive term in the repo today is the
  sym_trap varus/valgus penalty — a geometric prior. The prior exists precisely because
  the image signal is weak. A two-sided intensity/GO term would add genuine image signal
  for varus/valgus and IE rotation via the non-circular features (intercondylar notch,
  trochlear groove, condylar shoulders, bevels) rotating into/out of the projection — but
  ONLY if the template side renders attenuation/thickness, which it currently does not.
- Confidence: high for the conditioning diagnosis (Yamazaki abstract + geometry); medium
  for the degree of rescue achievable in THIS renderer (needs the new render target,
  unmeasured).
** Finding 3 — DIRECT_MAHFOUZ's intensity term is one-sided and cannot deliver the signal; it is also the cheapest place to add it correctly.
- In-repo verification: the intensity term computes the mean fluoroscopy intensity over template-white pixels (implant_mahfouz_metric.cu:129-156, 285-328; "(Sum of Pixel Input * Pixel Projected)/(Sum of Pixel Projected)"). For a rotation that preserves the silhouette, the sampled support is unchanged ⇒ the term is invariant. It is a silhouette-support-weighted fluoroscopy statistic, not a two-sided image comparison.
- The two-sided Mahfouz-style measure the literature actually uses compares a *rendered predicted image* against the fluoroscopy directly ("direct image-to-image") [Source: Mahfouz 2003 abstract; Mahfouz 2005's argument against segmentation variability]. To implement it, the renderer needs a per-pixel thickness/attenuation value; today FillTriangleKernel writes constant 255 (render_engine.cu:616-709) — no depth target. Adding a min-z/attenuation accumulation in the existing fragment-fill pipeline is a contained change.
- Black_Silhouette is registered (CostFunctionManager.cpp:426) but gates nothing in the GPU metric; it is only name-scanned into the stage-param struct (optimizer_stage_script.cpp:187-199). The recon's "dead config" claim is correct in effect (no kernel behavior depends on it).
- Confidence: high (verified in-repo).
** Finding 4 — Curvature: "tried and failed" is wrong — it was never measured; but the concept as scoped (local per-keypoint heatmaps) was also ill-specified, and local curvature is provably invariant for circular boundaries.
- In-repo verification: CurvatureHeatmapMetric returns constant 0.0 with an empty kernel (curvature_hausdorf_metric.cu:12-34, 70-71); never registered, never called. The CPU utilities (Menger curvature, inflection keypoints, per-keypoint heatmaps) work but are per-keypoint-local and CPU-side — unusable at 7k evals/s.
- Physics: curvature of a contour is a second-order (noise-amplified) quantity [Worring & Smeulders 1992; Kerautret-Lachaud 2008], and for a circular boundary segment (condyle arc, head, cup rim) curvature is CONSTANT along the arc ⇒ invariant under rotation about the arc center — the very DOF being attacked. Local curvature features attack a global symmetry/conditioning ambiguity with a feature that is blind exactly where the ambiguity lives, unless aggregated globally.
- The fair-test version would be a *global* contour-shape term: curvature profile / CSS-style descriptor of the whole rendered silhouette vs the precomputed fluoroscopic contour curvature map (CSS is the established robust global contour descriptor, Mokhtarian 1993/1996). This is pose-sensitive (template silhouette changes with pose) and symmetry-sensitive for non-circular contours. But it requires per-eval contour extraction + curvature on the template side — the tightest budget item (see Finding 6).
- Verdict: the owner's belief ("curvature heatmaps were tried and still not great") fails on the facts (never implemented), but the deeper challenge stands: as scoped (local keypoint heatmaps) curvature was the wrong tool; as a global contour term it is a plausible-but-unproven feature with no published implant-2D-3D precedent found in this research.
- Confidence: high (repo facts + geometry); medium (no published precedent for the global-curvature implant term — absence of evidence).
** Finding 5 — Continuous vs mirror symmetry must be separated, and the repo already has the mirror half.
- Continuous (stems, heads, cylindrical cups): no local gradient, cost flat, provably unrecoverable from the single-plane image alone (Finding 1). No feature fixes it; only external reference/priors/multi-view.
- Mirror (tibial tray mirror poses, cups' anterior/posterior tilt pair, sagittal-symmetric knee components): two discrete poses with near-identical projections; the cost still has working local gradients at each minimum — the problem is a global ambiguity, not missing signal. Hermans 2007 ICCV documents exactly this for knee implants (sagittal-plane symmetry → two significantly different poses with near-identical projections; statistical identification of the two solutions) [Source: mlanthology ICCV 2007]. The repo's domain sym-trap directive (CalculateSymTrap sweep, Crane-Duffy dyads, compute_mirror_pose) IS this class of machinery — angle 02 owns its completion. Distinct from the compute-side sym_trap_function varus/valgus penalty (a continuous-DOF prior) — recon explicitly warns not to conflate the two, and this report does not.
- Consequence for feature work: for mirror-ambiguous parts, signal engineering is NOT the fix (signal exists); for continuous-symmetric parts, signal engineering is IMPOSSIBLE; only for ill-conditioned-but-asymmetric parts (knee femoral component) is signal engineering the right lever.
- Confidence: high.
** Finding 6 — GPU budget: the two-sided intensity/GO features fit ~143 µs/eval; per-eval contour curvature is the tight squeeze; the fluoroscopy side must be precomputed per frame.
- Baseline: ~7,000 evals/s ≈ 143 µs/eval, ~15 kernels + 5 sync D2H copies, sync-latency-bound (repo recon; prior architecture-grounding synthesis). Every new per-eval kernel adds launch + latency; the D2H copy count is the scarce resource.
- Free per eval: anything computed once per frame on the fluoroscopy side (gradient/GO maps, distance maps, edge-dilation frames, contour curvature maps, ROI masks). The existing DistanceMapMetric/dilated-edge frames already exploit this; curvature_utilities.cpp belongs HERE (per-frame preprocessing), not in the per-eval loop.
- Per-eval costs (informed estimates on RTX 3090 Ti, to be measured with the jtml.z_profile-style instrument): thickness/attenuation render target: +1 fill-mode in the existing fragment pipeline, ~10-20 µs; template Sobel: +2 kernels ~5-10 µs; GO/GC comparison: one orientation-bin reduction kernel ~10-20 µs; pattern intensity: ~20-40 µs; Mahfouz two-sided NCC over ROI: ~10-20 µs (reductions already available via CUB). Total realistic add for intensity+GO: ~40-70 µs ⇒ ~5-6k evals/s — acceptable for a 15-20 s run.
- Per-eval boundary curvature (GPU EDT of the rendered mask + level-set curvature, or CSS of extracted contour): +3-5 kernels / 20-50 µs and, worse, it is a second-order feature computed on an aliased raster silhouette each eval — the highest risk/benefit ratio of all candidates. If pursued, specify it as a global contour term with defined semantics (the 2026 de-scope of the old stub was for undefined semantics — that critique survives).
- Confidence: medium (budget estimates are extrapolations from the measured baseline; the cost *structure* — precompute-per-frame vs per-eval — is high confidence).

* Implications for JTML (concrete, cost-aware, R15-safe)
1. **Do not resurrect the local per-keypoint GPU curvature metric.** It was never implemented, its semantics were undefined (2026 de-scope verdict), and local curvature is blind exactly at circular boundaries. Complete the pending de-scope hygiene item (remove AllocateCurvatureHausdorfScore at DIRECT_DILATION.cpp:42-43 + banner). If curvature is ever wanted, it must be a *global* contour-shape term with defined semantics — schedule as a separate, measured experiment, not a port.
2. **Cheapest high-value change: make DIRECT_MAHFOUZ two-sided.** (a) Add a thickness/attenuation render target to render_engine.cu (accumulate per-pixel path-length in FillTriangleKernel or a sibling kernel; keep flat-fill mode bit-identical for existing variants — R15). (b) Add a kernel comparing the rendered thickness image to the fluoroscopy intensity frame with an NCC/pattern-intensity-style term (pattern intensity is the documented choice for content mismatch: bone/cement edges present in X-ray but not in the model — Weese 1999; Penney 1998). (c) Register it as a NEW variant (e.g., DIRECT_MAHFOUZ_T2) following the per-variant pattern: explicit .cpp in src/compute, explicit CMakeLists entry, CostFunctionManager registration, 51-entry registry golden fixture update (cost_function_registry_test). Zero changes to direct_optimizer.h:28 seam or optimizer — the cheapest possible fix surface, as the owner hypothesized.
3. **Add a gradient-orientation (GO) term** — the single best-documented metric under implant/instrument content mismatch (De Silva 2016: 0% gross failures unmasked). Fluoroscopy GO map precomputed once per frame; per-eval = template Sobel + orientation comparison. Same variant-registration path as (2). The current DistanceMapMetric edge-to-template and FastImplantDilationMetric overlap stay untouched.
4. **Before wiring weights, measure valley depth per weak DOF** with the existing jtml.z_profile instrument (and extend it to rotation sweeps around the AP axis): the deciding number is whether the new term deepens the varus/valgus and IE basins. This is the R15-safe validation path (measurement, not re-derivation) and directly answers "does the new feature carry signal about THIS DOF."
5. **Do not promise image signal for continuous-symmetric parts.** If hip/shoulder scope proceeds: stem version (circular/tapered-stem class) and cup rotation about the symmetry axis are information floors — the evidence-backed routes are external reference (D'Isidoro's pelvic-bone matching [cmbbe2018]), kinematic priors (the existing sym_trap penalty pattern), multi-view (TREA patent), or dyad/priors work owned by angle 02. Angle 01's boundary: the seam can carry priors (it already does — sym_trap_function), but no image feature in this family recovers a symmetric DOF.
6. **Re-purpose curvature_utilities.cpp as per-frame fluoroscopy preprocessing** (contour curvature map, per-keypoint heatmaps at frame rate, not eval rate) — that is where the working CPU code is cost-effective; keep it out of the 143 µs loop.
7. **Feature/DOF classification to hand to angle 05 and angle 02**: for each implant class, label weak DOFs as (a) continuous-floor (stem version, head orientation, cylindrical-cup rotation) → priors/external reference; (b) mirror-ambiguous (tray, sagittal knee components — Hermans 2007; repo dyads) → disambiguation, signal exists; (c) ill-conditioned (knee femoral varus/valgus, depth) → two-sided intensity/GO features + conditioning priors. Only (c) is a signal-engineering problem.
