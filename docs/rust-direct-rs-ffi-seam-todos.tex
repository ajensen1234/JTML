\subsection{{\bfseries\sffamily TODO} Declare \texttt{build\_cpp\_cost} in the bridge [BLOCKER]}

\subsubsection{Walkthrough — getting a CppCost into Rust's hands}
\label{sec:orge6e6bc8}

\textbf{Where you're starting:} the bridge knows CppCost EXISTS but has no way
to CREATE one:

\begin{minted}[]{rust}
   // rust/direct-rs/src/lib.rs (current)
   unsafe extern "C++" {
       include!("domain/cost.h");
       include!("domain/data_structures_6D.h");
       type CppCost;
       type Point6D;
       pub fn evaluate(self: &CppCost, point: &Point6D) -> f64;
   }
\end{minted}

and C++ offers exactly one factory, whose parameter cxx cannot spell:

\begin{minted}[]{cpp}
   // include/domain/cost.h:54
   std::unique_ptr<CppCost> build_cpp_cost(CppCost::CostFunction fn);
   //                        ^^^^^^^^^^^^^^^^^^^^^^^ std::function<double(const Point6D&)>
   //                        cxx has NO representation for std::function — period.
\end{minted}

\textbf{Q1 — warm-up.} Why can't the declaration above be fixed by simply
adding \texttt{fn build\_cpp\_cost(fn: ???) -> UniquePtr<CppCost>;}? Name the
exact reason std::function is unspellable, and therefore what property
every argument of EVERY function you ever declare in an extern ``C++''
block must have.

\textbf{Q2 — who owns the real cost at runtime?} Open
optimizer\textsubscript{manager.cpp}:1745-1788 (BuildGpuCostAdapter) and identify
what the lambda captures (gpu\textsubscript{principal}\textsubscript{model}\_, calibration\_,
stage\textsubscript{manager}). Question: could ANY of those captures cross the FFI as
arguments to a Rust-called factory? If not, what does that force the
construction direction to be — C++ builds and hands over, or Rust calls
in with plain args?

\textbf{Q3 — the two doors.} cxx gives you exactly two ways for a
UniquePtr<CppCost> to come into existence on the Rust side. Write both
declarative forms from memory, then check yourself:

\begin{minted}[]{rust}

   ___ build_cpp_cost(___) -> UniquePtr<CppCost>;

   // Door 2: declare the C++ CONSTRUCTOR itself
   // (cxx maps `fn new(...) -> UniquePtr<CppCost>` to CppCost(...))
   ___ new(___) -> UniquePtr<CppCost>;
\end{minted}

Hint: cost.h:38 shows CppCost has TWO ctors — default and
explicit(CostFunction). Only one of them is declarable. Why?

\textbf{Q4 — the argument problem.} Whichever door you pick, the factory needs
to know WHICH cost to seal. Brainstorm three candidate argument shapes
(nothing / a small enum tag / something richer), and for each ask:
``could the GPU adapter's captured state be recovered from this at the
C++ end?'' Record which one survives.

\textbf{Q5 — write it.} Add your chosen declaration to lib.rs (don't forget
use cxx::UniquePtr;), plus whatever minimal arg-less overload cost.h
needs. Compile with cargo check.

\textbf{Decision to record:} construction direction (who calls whom), and
whether build\textsubscript{cpp}\textsubscript{cost} stays in cost.h or gets a sibling. One sentence
under this heading when you've decided.

\textbf{Checkpoint:} a \#[cfg(test)] test in the crate can obtain a
UniquePtr<CppCost> without panicking (it may be unbound — that's fine,
the IsBound guard item covers that separately).

yourself.)

\begin{minted}[]{rust}
