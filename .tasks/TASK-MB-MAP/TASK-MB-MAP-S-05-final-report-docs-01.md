## Executive Summary

The JTML codebase has **no automated test framework** (no Catch2, GTest, CTest, etc.). The two test executables in `test/` are hand-written integration/smoke tests: one verifies VTK rendering plumbing, the other is a stub that prints "Hello World." There are no unit tests, no CI quality gates, and no `ctest` configuration. Quality gates are purely build-and-tidy: `pixi run build` + `pixi run tidy`.

`shape_sensitivity/` is a standalone research executable that sweeps bone-model rotations through 3D space and outputs shape-descriptor CSVs (IARTD and Hu moments), used to characterize implant recognition sensitivity prior to ML training. `Study2Grid/` is a standalone data-preparation pipeline that ingests hierarchically organised fluoroscopy study directories and outputs grid-formatted TIFF images with silhouette labels for ML training.

Example studies (`Kneel_1`, `Subject0`) demonstrate the two expected data formats: single-plane (monoplane with `JT_INTCALIB` calibration + `JT_EULER_312` kinematics `.jts`) and biplane (two camera dirs + `.jtak` files).

The smart pointer conversion effort covered **73 tasks** (tasks 0-72) generated by a Python/bash orchestration harness. The majority of tasks resulted in "CONVERTED – no raw pointers found" or "SKIPPED," indicating the core codebase was already largely clean or used framework-managed pointers (VTK smart pointers, Qt parent-child). CUDA device pointers are intentionally left as raw pointers; two custom deleters (`CudaFreeDeleter`, `CudaFreeHostDeleter`) were added to `include/gpu/cuda_deleters.cuh` to support RAII wrappers for device/pinned memory.

## 2. shape_sensitivity Module

### 2.1 Purpose

**Fact** (`src/shape_sensitivity/main.cpp:12-250`): `shape_sensitivity` is a standalone executable (`shape-sensitivity` target) that performs a **3D rotation sweep** of an implant model and computes shape descriptors at each pose. It outputs two CSV files:
- `iartd-{model}.csv` — IARTD (Invariant Angular Radial Transform Descriptor) finite-difference sensitivities (dx, dy, dz) for each rotation step
- `hu_moments-{model}.csv` — Hu moments with finite-difference sensitivities

This is a research tool for characterising how sensitive image shape descriptors are to bone orientation changes, presumably used to inform feature design or validate cost function reliability.

### 2.2 Structure

**Fact** (`src/shape_sensitivity/CMakeLists.txt`): Standalone executable with files:

| File | Role |
|------|------|
| `main.cpp` | Rotation sweep loop, CSV output |
| `descriptors.h/.cpp` | `calculateIARTD()` wrapper |
| `art.cuh/.cu` | `img_desc` CUDA class — ART moments (real/imag via `art_n_p()`) + Hu moments on GPU |
| `iartd.h` | `IARTD` class stub (interface only, no implementation visible) |
| `matrix_vector_utils.h/.cpp` | Vector difference utilities, rotation nudge helpers |

**Fact** (`src/shape_sensitivity/art.cuh:13-36`): `img_desc` stores raw device pointers (`dev_Fnp_re`, `dev_Fnp_imag`, `dev_raw_img_moments_`) and host pointers (`Fnp_re`, `raw_img_moments_`) — these remain raw per the CUDA exclusion rule.

**Fact** (`src/shape_sensitivity/main.cpp:23`): Uses `new img_desc(1024, 1024, 0)` (raw pointer, manually deleted on line 247). The GPU model is also `new GPUModel(...)` with `delete` on line 248.

*Inference*: The shape_sensitivity executable predates the smart pointer conversion work and still uses the old raw-pointer pattern. It was not included in the conversion task list (tasks were generated from the main `src/core`, `src/gpu`, `src/gui`, `include/` tree, not from `src/shape_sensitivity`).

### 2.3 Sweep Parameters

**Fact** (`src/shape_sensitivity/main.cpp:64-72`): Sweep ±30° in each axis with 5° steps = 13×13×13 = 2,197 poses. Each pose renders the model and calculates finite differences in x, y, z rotations.

## 3. Study2Grid Module

### 3.1 Purpose

**Fact** (`src/Study2Grid/main.cpp:74-976`): `Study2Grid` is a standalone data-preparation pipeline that:
1. Discovers fluoroscopy study directories recursively (`Patient → Session → Movement`)
2. Reads STL models, calibration files, and kinematics (`.jts` / `.jtak`) for each study
3. Renders GPU silhouette labels for each model at each frame pose
4. Writes resized/padded 1024×1024 TIFF images and label images to `Labels/` subdirs
5. Writes pose info logs (`.txt`) and optionally key-point label files (`_KPlabels.txt`)
6. Optionally projects 3D anatomical key points (`.kp` files) onto image plane and saves normalised coordinates

### 3.2 Structure

**Fact** (`src/Study2Grid/CMakeLists.txt`): Standalone executable `Study2Grid-Cmake` with files:

| File | Role |
|------|------|
| `Study.h/.cpp` | `Study` struct: holds all file paths and metadata for one fluoroscopy session |
| `FileParsers.h/.cpp` | Directory/file scanning helpers (`path_leaf_string_*` functors) |
| `ImageInfo.h/.cpp` | `ImageInfo` class: bundles image path, model types, label paths, poses, KP data |
| `BasicLinearAlgebraStructures.h/.cpp` | `XYPoint`, `XYZPoint`, `RotationMatrixZXY` |
| `KPReader.h/.cpp` | Reads `.kp` (key point) files |
| `STLReader.h/.cpp` | Reads any `.stl` file into triangle lists |
| `main.cpp` | Orchestration: sweep studies, render, write grids |

**Fact** (`src/Study2Grid/Study.h:38-67`): The `Study` struct records `stl_files_`, `calibration_`, `images_`, `kin_files_`, `study_dir_`, `width_`, `height_`, `patient_name_`, `sess_num_`, `mov_name_`, `mov_num_`, `stl_types_`, `stl_basenames_`, `stl_basenames_have_kp_`.

**Fact** (`src/Study2Grid/main.cpp:11-18`): The code has OS detection via `#ifdef defined(_WIN32)` but the `#ifdef defined(...)` construct is actually a preprocessor bug (always false — `#ifdef` with an expression is non-standard). *Inference*: `OS_WINDOWS` will always be 0, so Windows path separators are never used regardless of platform.

### 3.3 Grid Configuration

**Fact** (`src/Study2Grid/main.cpp:98-115`): Key variables are hardcoded in the source:
- `GPU_DEVICE = 0`
- `GRID_WIDTH = 1`, `GRID_HEIGHT = 1` (1×1 grids — one image per grid file)
- `IMAGE_HEIGHT = IMAGE_WIDTH = 1024`
- `USE_PADDING = true`, `INVERT_IMAGE = false`
- `RAND_SHUFFLE_IMGS = false`, `GENERATE_KP_DATA = true`, `RAND_INVERT = false`

*Inference*: This was described in a comment as "old way of doing things — the new way takes in a batch file" (line 79), suggesting Study2Grid is deprecated in favour of a batch-file driven variant.

### 4.3 Data Format Summary

| Field | Format |
|-------|--------|
| Calibration | Text file, first line = `JT_INTCALIB` or `JTA_INTCALIB`, then principal_distance, x_offset, y_offset, pixel_pitch |
| Kinematics | Text file, first line = `JT_EULER_312` or `JTA_EULER_KINEMATICS`, second line = header, rows = `x_tran,y_tran,z_tran,z_rot,x_rot,y_rot` |
| Images | `.tif` or `.tiff`, grayscale, typically 1024×1024 |
| Models | Binary or ASCII `.stl` |
| Key Points | `.kp` files with 3D XYZ tuples per landmark |
