* Baseline / Oracle Verification

This file is the authoritative oracle spec (referenced by docs/brainstorms/... and
docs/plans/2026-08-07-001-...). The oracle is a *behavior-preservation* gate: it catches
regression (drift from current known-good behavior), not latent correctness bugs.

**Compare reference (two-tier, per the plan):**
- Tier 1 (CI, headless, CPU): the extracted `DirectOptimizer` (test/unit/
test_direct_optimizer.cpp) converges on an analytic cost function. Deterministic, no GPU.
- Tier 2 (GPU-labeled, gpu machine): run the real pipeline on Kneel_1; at the final
  optimized pose, project the implant (DRR) and assert the rendered silhouette matches
the known-good `Labels` (B) within a pixel-diff / IoU threshold. This appearance-based
gate is the robust one: DIRECT numeric convergence is noisy, so ABSOLUTE pose-vs-`fem.jts`
is treated as informational only (not the hard gate).

**Baseline:** (C) `fem.jts` gives the starting/known-good pose; (F) `fem_oracle.jtak` is the
actual captured Qt5/GPU output. The captured pose and the known-good projection (B) are the
reference. Tolerance on the RENDERED silhouette is the load-bearing comparison.

**Settings (authoritative):** DIRECT_DILATION for the femur; trunk / 2-branch / 1-leaf;
~10000 iteration budget per stage; ranges trunk +/-30, branch +/-20, leaf +/-3 (z opened to
~100); dilation trunk 6px / branch 3px / leaf 1px. (Note the budget is cumulative across
stages, so effective caps are ~10k/20k/30k.)
